# 音源库检索与选材

> 音源库 = SQLite + FTS5 单文件 DB（`foley_project.json` 的 `asset_db` 指向），由 pipeline 的 `build_asset_db.py` 扫描音源根目录构建。本手册不含具体库路径。

## DB 结构

```sql
assets(id, path UNIQUE, filename, category, name, desc,
       duration, samplerate, n_cues, theme, rating, official)
cues(asset_id → assets.id, offset_sec, len_sec, label)   -- 官方 cue 区（覆盖率低）
assets_fts(name, desc, category)                          -- FTS5 内容索引
```

- `rating`（1~5）：用户在 DAW 里打过分的音效 = 质量背书，高分优先。
- `official`：官方包名（检索/锁包主参考）；`category`：中文分类（辅助）。
- `theme`：`通用` / 题材（如中国风玄幻设计包）。

## q() 取路径模式（place 脚本标配）

```python
def q(db, name):   # 精确名优先，前缀兜底；取不到就报错，不硬编码绝对路径
    r = db.execute("SELECT path FROM assets WHERE name=?", (name,)).fetchone()
    if r: return r[0]
    r = db.execute("SELECT path FROM assets WHERE name LIKE ?", (name+'%',)).fetchone()
    if not r: raise RuntimeError(f"库里没有: {name}")
    return r[0]
```

每集开始建一张 `S = {别名: q("DB真名")}` 音源字典，cue 表里只写别名——一条一行，可读可查。

**条目命名（2026-09-09 用户拍板）**：REAPER 条目名一律写**源文件名 stem**（如 `CC-CK Body Fall Generic Cloth Soft 01`），不写动作描述——用户按包定位音源，文件名才能直接对应到库里的包。中文动作描述只出现在运行日志和 CUES 表 label 字段（对账打印用）。

## 关键词检索（交互式选材）

```python
db.execute("""SELECT name, path, rating FROM assets
  WHERE assets_fts MATCH ? AND category NOT IN (低优先级列表)
  ORDER BY rating DESC LIMIT 20""", ('"法术" AND "开启"',))
```

注意：FTS5 表没有 theme 列，题材过滤用 `JOIN assets a ON a.id=assets_fts.rowid`。
中文分词按 unicode61，中文召回一般——题材库正货可直接 SQL `name LIKE` 直取。

## DB 路径迁移（换机必读）

DB 里 `path` 是建库机器的绝对路径。音源盘原样迁移则直接能用；否则批量替换前缀：

```sql
UPDATE assets SET path = replace(path, '<旧前缀>', '<新前缀>') WHERE path LIKE '<旧前缀>%';
```

全新音源库：改 pipeline `config.json` 的 `library.roots`（通用包）+ `theme_roots`（题材包），跑 `build_asset_db.py` 重建，`search_assets.py "关键词"` 自测。FTS5 报 `no such module: fts5` = 换 Python（官方编译版自带）。

## 选材终审六问（每条 cue 定稿前必过；2026-09-23 起试行，验证至下次更换新视频）

> 操作层只有这六问。**任何一问拿不准 → 进存疑清单，不硬贴。**六问本身不再增加条目——新的翻车教训只进末节反例库，防稀释。

1. **事件对位**——配的是帧里真实发生的事件吗？画面判读有疑 → 上报，任何人不改判。
2. **声源存在**——这个声源在画面世界里存在吗？（可见金属件才配金属声；古风画面无机车引擎）
3. **档位对位**——力度×体型档位匹配吗？（cue 轻/弱 ↔ 素材名 Massive/Hard 冲突即存疑；Large/Huge cue 配 Soft/Small 同判；机器化落地见下节）
4. **质感域对位**——题材/元素/材质在同一个世界吗？（题材开工前判定并写入项目 `genre`，检索管线按域标签自动降权对域素材：玄幻不选科技域、金光不配火/电系、金属只配可见金属件）
5. **空间对位**——far/mid/close 与景别远近一致吗？（远山炸开 = far 档，近景摩擦 = close）
6. **结构对位**——movement/impact/whoosh 优先级选对了吗（见语言策略节）？起手/收尾齐全吗？

### 硬约束（流程层，长期有效，不占六问）

| 约束 | 内容 |
|------|------|
| 集内同源 ≤2 次 | 同一源文件一集最多 2 条 cue（主事件最多 3 次且间隔>30s）；邻近 cue 异窗轮换，同源多次必须取不同时间窗 |
| 星级不硬卡 | 5★ 内部随机仅适用中档以上 impact；弱/轻类 cue 不做星级与 Designed 加权——星级是质量背书，不是匹配度背书 |
| 锁包检索 | 动作→官方包映射（`action_packs`），包内候选再加分；锁包空结果自动退全库，宁可全库不空手 |
| 素材层政策 | Designed 优先（+0.5）；CK 素材层降权保留（-2）；Source Audio 剔除 |
| 低优先级降权 | 枪战/猛禽/烟火等气质不符分类 -8（config `low_priority_categories`） |
| 脚步不配 | 脚步/怪物足步/爬行步检索命中也不选，归【手动】人工（步频无法与画面对齐） |
| 杂集末位 | duration >10s 杂集/compilation 默认不作候选；确需使用须全窗 volumedetect 有声证据 + 存疑放行 |
| 非零 offset 验窗 | start_offset 默认 0 头部起播；确需取窗先跑 `ffmpeg -ss <off> -t <len> -af volumedetect`，max_volume > −30dB 才允许 |

## 语言策略与语义防御

- **Boom 库用英文理解和检索**（翻译会偏义）；中文动作先映射英文关键词（打→punch/hit、脚步→footstep）。纯中文命名的题材库不受此限。
- **检索主词 = 动作，材质词低权重辅助（20260916 制作人条款）**：上游报告的事件主词是动作（抽出/递出/扶立柱），检索以**动作词为主词、第一权重**；材质词（金属/木质/玻璃/纸）作包内过滤与降权辅助——材质词不是禁用，是权重排序：动作词定类，材质词收窄。反例：以「金属」为主词检索 → 命中 Massive Bar Rattle 钢铁落地声去配「手扶立柱轻吱」——动作优先原则在选材端的延续。
- 扩展词带**主体限定**（人走路→human boots footsteps，不引入 horse）与**限定短语**（拍手→hand clap，不裸 clap 防 thunderclap）。
- 复合词连写+分写双给（underwater + under water），FTS5 token 层面两者不等价。
- 同系列资产（同一组的 Impact/Movement/Whoosh × 档位）要列全再挑，按字母序取会漏类。
- 飞掠 = 无源风切 whoosh，**别选具体声源**（车/飞机引擎在古风画面穿帮）；命中后过一遍「这个声源在画面世界里存在吗」。
- 无实体能量体（雾/烟/暗影/黑气）的移动翻涌：方向为气体类（wind/hiss/steam）或暗系魔法（evil 等标签）；无实体对象没有「正确音色」，主观性强——拿捏不准宁可不贴，进存疑清单。

## 声学结构判断（贴轨前必做）

- **贴长条前查源结构**：`ffmpeg -i x.wav -af silencedetect=noise=-35dB:d=0.3 -f null -` 解析静音边界。0~2 个边界 = 连续型可任意取窗；**5+ 个边界 = oneshot 序列，禁止拉长硬拼**（两发硬拼 = 假连续）。
- 需要连续质感找**长连续源**（风声/引擎类 60s+ 文件），直接取窗自带真实起伏。
- 同源多次使用必须切段或取不同相位窗，**禁止每次都播同一段**。
- 同一视觉事件 = 多个声学瞬间：出水→入水、发射→命中、跃出→砸落。每个事件问「收尾声在哪」，缺尾不完整。
- 力度档位 = 主体体型 × 动作幅度：庞然大物用 Large/Huge，人级用 Small/Medium。
- 巨物的「重」靠低频含量与冲击感传达：巨物 movement 优先低频 whoosh、冲击型 whoosh、生物包翼振类（wing feather/leather，large/medium 档）、破空声。
- 文件名的动词就是力度标签：`Cloth movement`=小幅持续，`throw`=甩掷力度；默认小幅度，明确发力才用 whoosh/hard。
- **whoosh vs movement 词族优先级（20260916 制作人条款，检索与报告两端同规）**：whoosh 词族**第一优先**服务转场与明显快速位移（镜头转场、扫镜、快速挥掠、飞掠、急冲）；慢速肢体与物品动作（拿起、放下、递出、接过、转身、翻动、拖拽）**movement/rustle 词族第一优先**，whoosh 不作首选——仅当画面确有叠加的快速位移成分（如手臂快速甩动入画）才作补充层。是优先级排序，不是非此即彼的禁区。

## 力度/质感对位机器化落地（六问·问3 展开，20260916 金属撞击事故沉淀）

**事故复盘**：cue「扶立柱金属轻吱(弱)」→ 选中 `CH-CK Metal Massive Bar Rattle`（Cinematic Hits 电影冲击库，5★）→ 听感 = 钢铁落地。口径方向没错（人手扶金属立柱，轻金属吱是合规拟音），错在选材：①只匹配材质词「金属」，**没校验力度词**——素材名里 Massive/Rattle 与诉求 轻/吱 逐字冲突却无人看；②「5★前置」「Designed +0.5」两条规则把它顶上候选首位——**星级是质量背书，不是匹配度背书**；③AI 无试听，质感错配没有人工闸门兜底。

**选材三问（每条 cue 定稿前必过；前两问机器可查）**：

1. **力度对位**：cue 标注为 轻/弱/Small/Medium → 素材名含 `Massive/Huge/Hard/Large/Impact/Hits/Smash` 的**直接判存疑**（进存疑音色清单，放行后才贴）；反之 Large/Huge 的 cue 配 `Soft/Light/Small` 素材同样判存疑。文件名力度词与 label 力度词默认同档。
2. **素材层对位**：轻/弱互动声（手扶、轻碰、摩擦）**foley/movement 库第一优先**，Designed/Cinematic Hits 冲击库不作首选；冲击库服务口径明确的大 impact。
3. **声源存在性**（既有条款）：这个声源在画面世界里存在吗。

**机器化落地**：place 脚本生成后自检一遍——label 强度词（轻/弱/重/大 + Small/Medium/Large/Huge）与素材名强度词冲突的条目，自动列入交班报告**存疑音色清单**，未经总监/制作人放行不得贴。**弱/轻类 cue 检索时 rating 不做前置加权、Designed 冲击类库降权到候选末位**（星级与 Designed 加权只服务中档以上 impact）。

## 检索管线（pipeline 里的 search_assets.py）

链路：中文查询 → LLM 扩展英文关键词+排除词（模型可配，主体限定/排除词质量优先选强模型）→ 两阶段（action_packs 锁包 → 包内 FTS5 bm25）→ 锁包空结果**自动退回全库**（宁可全库不空手）→ 中文类别加分 → 分类先导 +8 → 过滤/加权。静态映射优先、LLM 只兜长尾；三条防副作用机制：触发词只匹配查询词本身、排除词与检索词冲突时弃用排除词、rating 加分需语义 token 交集。

**题材域过滤（2026-09-23 试行）**：`search(..., genre="玄幻")` 按 config `library.domain_tags` 把对域素材（科技域 official/分类）降权压末位（-8，**降权非排除**，宁可末位不空手；命中映射见 `genre_domain_block`）。题材写入 `foley_project.json` 的 `genre` 字段（`project_config.py init --genre`），选材开工前先定题材。手工 SQL 检索（不经引擎）时自行加 `AND official NOT IN (...)`/`AND category NOT IN (...)` 等效过滤，域清单以 config 为准。
