# 视频动作分析（视频 → 声音事件报告，带出厂门禁）

> 目标：拿到任意视频，产出一份**逐秒时间轴报告**，标注每个时间点「画面在做什么、该听见什么声音、属于哪类」。贴轨方拿到报告即可直接检索贴轨，无需再看视频。
> 下游消费者：`reaper-foley-workflow`（贴轨方按报告的【自动】条目检索贴轨）。

## 三条铁律（2026-09 权臣CP 54 集塌方换来的，先读再动手）

1. **判读必须逐秒落盘 `per_second.jsonl`，报告表格从它誊写**。不落盘的长会话必然无感降级成梗概——实测一夜连跑 54 集，表行数从 22 行/集一路跌到 11 行/集，且每份报告头部仍自称「逐秒全扫」。降级是静默的，自己察觉不到，只有落盘产物能证明粒度。
2. **交付前必须过 `scripts/check_report.py` 门禁**，任何 FAIL 不许交付、不许开下一集。内容级红线（合并行、行数下限、统计凑数、帧证据存在性）必须机器查，人工复查会漏（塌方当夜的 QC 只查了文件覆盖和标签规范，54 集全军覆没却「103/103 通过」）。
3. **秒↔帧以 `manifest.json` 为准**。`s_%03d.jpg` 从 1 起编号、时间从 0 起算，`s_059` 是 t=58s——权臣CP两版报告都按「s_N=第N秒」引用，cue 点整体偏移 +1s。报告一律写**秒**，引用帧证据时写「帧s_060(t=59s)」格式。

## 工具链

- ffmpeg / ffprobe（PATH 内）
- 本 skill 自带脚本：
  - `scripts/extract_frames.py` — 抽帧 + 生成 manifest.json（秒↔帧权威映射，双轮时长复核；默认 480p 出帧省 token）
  - `scripts/check_report.py` — 出厂门禁（合并行/行数/空洞/统计凑数/帧存在性/人名/章节齐全）
- 视觉判读：多模态原生读图（Read 逐张看图）

## 流程（三段式，段段落盘）

### 第一步：抽帧

```bash
python scripts/extract_frames.py <video> frames_<集号>/              # 1fps 全量，正式报告必须
python scripts/extract_frames.py <video> frames_<集号>/ --fps 3 --start 55 --end 62   # 快速动作段加密
```

- 粗扫（3s/帧）只可用于预览剧情，**正式报告禁止用粗扫数据**（实测粗扫时间偏差 2~5s，机枪开火级别的事件都会整段漏掉）
- 快速动作段（打斗、鞭击、连续碰撞）用 2~4fps 加密确认**起手帧**，并在报告注明加密窗口
- **默认 480p 出帧（2026-09-21 制作人条款，`--scale` 默认 480）**：识别目标是画面中人物的动作与明显需要音效的事物，不依赖高清细节；帧分辨率直接决定批量读图的视觉 token 消耗，480p 对判读与下游帧证据核验都足够。仅当需要更细证据（小物件接触判定等）时临时 `--scale` 调高。manifest 记录实际 scale 供追溯
- 每个视频独立帧目录 + manifest.json；manifest 是秒↔帧唯一权威，后续判读/报告/门禁都引用它

### 第二步：逐帧判读 → per_second.jsonl

逐张 Read 帧图，**每秒落一行 JSON**（同秒多层事件可多行）：

```json
{"sec":58,"shot":"旷野横移","subjects":["玄袍男子"],"action":"白羽箭贴画面横飞(运动模糊)","evidence":["frames/26/s_059.jpg"],"sound":[{"event":"箭矢风切whoosh","onset":58.0,"tail":59.0,"note":"递进加速;放箭点未入画,弓弦可垫57.5"}],"type":"自动","confidence":"high"}
```

- `type` ∈ 自动/手动/对白/待定；静态、对白秒**也落行**（action 写「静态/对白延续」）——留白行证明「没漏看」
- `action` 必须能指认前后帧差异；写不出帧差就不许写动作（假动作防御，见判断准则 #6）
- 写「未见X」之前先核对 manifest 与帧文件——塌方案例对着自家帧库写下「箭已躺在地上，未见飞行」，而 s_059/s_060 两帧就是横飞与中肩
- 判读可跨会话续跑：新会话只信磁盘（manifest + 已落盘行），不信上一会话的记忆

### 第三步：渲染报告 + 出厂门禁

从 jsonl 逐行誊写报告表格（模板见下），然后**必须**：

```bash
python scripts/check_report.py --report 第26集.md --duration 65.2 \
    --frames frames_26/ --ban-names <剧中人名,逗号分隔>
# 批量: --dir <报告目录> --durations durations.txt（每行 "集号 秒"）
```

- 任何 FAIL = 不许交付、不许开下一集。PASS 后人工只复核判读力问题（假动作、音色选型），粒度问题已由门禁兜底

## 判断准则（核心经验，按此判读声音事件）

> **总纲：动作优先（20260916 制作人条款）**——动作判定永远第一步、优先级最高：先判「谁在做什么动作」（movement 还是 impact、起手→发生→收尾、力度档位），动作成立之后才考虑次要属性（材质、器物、UI）。**每条声音事件的文字描述以动作开头为第一顺位**（「取出信封动作：纸面摩擦轻响」），材质词置于后置括号备注（「纸材质」）——这是书写次序的优先级，材质信息本身要保留，只是不占主词位。下游选材按事件主词检索——材质当主词 = 「金属撞击配人动作」类事故的直接源头（20260916 实案：报告写「扶立柱金属轻吱」→ 选材只匹配到「金属」→ 选中 Massive Bar Rattle 钢铁落地声）。

1. **动作的时间结构**：一个视觉事件 = 多个声学瞬间（起手→发生→收尾）。对每个事件问：「**收尾声在哪？**」缺尾不完整。
2. **movement ≠ impact ≠ whoosh，选型是优先级问题（20260916 制作人条款）**：画面在「动」（走/飞/游/掠）配 movement 类；画面在「撞」（落地/入水/碰撞/命中）配 impact 类。水下移动不是 impact。**whoosh 的第一优先场景是转场与明显快速位移**——镜头转场、扫镜、快速挥掠、飞掠、急冲（空气被快速推开的风切质感）；**慢速/小幅度的肢体与物品动作——拿起、放下、递出、接过、转身、翻动、拖拽——movement 是第一优先**（质感来自材质摩擦与接触），whoosh 不作首选、仅当画面确有叠加的快速位移成分（如递出时手臂快速甩动入画）才作补充层考虑。这是优先级排序，不是非此即彼的禁区。
3. **飞掠**：飞行物掠过 = 无源风切 whoosh，禁止配具体声源（汽车/引擎在古风画面里穿帮）。命中前过一遍「这个声源在画面世界里存在吗」。
4. **加速运动标「递进」**：底衬渐入 + 呼啸渐强 + 顶点交给 hit，不许一条 whoosh 平铺。
5. **力度档位 = 体型 × 幅度**：人级 Small/Medium，大型主体 Large/Huge。报告标注主体体积。
6. **假动作防御（最高红线）**：只配**亲眼从帧里确认**的动作过程。静态姿势（托腮、倚靠、手扶）不许脑补成动作；叙事动词的字面联想不可信（「被拦停」≠ 撞击）。帧证据不足就如实写「帧证据不足」并放入待拍板，**不许编**——也不许把真实动作「读没」（见教训存档白羽箭案）。
7. **跨镜头剪辑点**的事件音，标注「跨切点，需延长+淡出」。
8. **人声一律不标（2026-09-11 制作人修订）**：台词、哭喊、痛呼、尖叫、哼哈、喘息、冷笑等**所有人声（含打斗语气音）都由配音环节的人声/对白轨覆盖**，不属于音效识别范围——标【对白】保留行即可，不配。**动物叫声（兽吼、马嘶、犬吠、画面可见动物的鸣叫）是正货【自动】事件**（音源库可检索素材），不随配音走。狮子张口无声仍是穿帮画面，但那是配音环节的活，不是报告的活。
9. **人物只写外观特征**（「紫甲男子」「灰发老者」），禁止写人名/人物小传/剧情解说——片内名卡出现的人名也不许写进报告。
10. **器物声主次随表现意图走，不随道具清单走（2026-09-11 权臣CP 两面教训）**：先判这一帧的表现力本体在器物还是在人——
    - **器物声当主角**：动作的命中点/表现点落在器物上（兵器互击、摔杯、拍案、器物大特写慢动作）。此时器物声就是 impact，标全「起手挥动→命中碰撞→余响」，力度档位跟动作力度走；
    - **人物声当主角**：生活化持物（喝茶、递物、把玩），器物只是手中道具。器物声**只在三种帧证据可证的接触下标注**——①明显碰撞/击打；②拿起与放下瞬间的离面/触面帧；③器物与手可见相对滑动。手持器物悬空微调、捧器物平稳抬起、持器物入画未触——一律不标器物声；
    - **判定三问**：命中点落在器物还是人的姿态？导演给这件器物几帧/给没给特写？剪掉这个声音画面表达损失什么？
    - **为贴轨写作**：逐秒报告是 cue 施工单，每行声源＝下游配乐权重。写完问一句「下游拿到这行会先配什么，这是我想要的吗」；器物声不得在无接触证据时压过人物动作。

## 环境底衬规则（2026-09-11 第二次修订：场景级环境定场为必写项）

- **逐秒行内不写环境**：持续段不许逐行重复环境描述，逐秒行只写动作与事件。
- **场景级环境定场是必写项**：每个场景切换的第一秒（含全片第一秒），在画面列/声音列标注该场景的**时间+地点**（如「白天·庄园庭院」「夜晚·室内书房」），供贴轨环节铺设环境底衬（风噪、鸟叫、室内底等）。仿真人剧集常靠纯对话推进，环境定场往往是对话段的唯一环境信息来源，不可省略。
- 环境定场**不计入【自动】事件统计**，统计只数离散动作/特效事件。
- 环境底衬的细节铺法（几层、什么声音、音量层次）由贴轨环节自行处理，报告只负责把场景事实说清。
- 同一场景持续段发生的时间/光照变化（如白天转黄昏）按新场景处理，补一条定场。
- **全片环境判断是必写项（2026-09-22 制作人条款）**：除逐场景定场外，报告须对**全片整体环境**出一条判断——综合各场景定场归纳全片时空底色（如「全片均为白天·麦田/田野户外」），并给出**候选环境底衬声方向**（如：风噪、风吹树叶/草地声；城市街景则给车流底、人群嗡声等）。判不出统一底色就如实写「场景混杂，无全片统一环境」，按场景分别给候选方向。候选方向是给贴轨环节的选材指引，具体铺设（几层、音量层次）仍由贴轨环节处理，报告不定死。
- **识别产出仍是两类**：①动作（谁在做什么，起手→发生→收尾，帧差可证）；②明显需要音效的地方（人物动作、动物动作与叫声、作为命中点的器物碰撞等）。**人声不在识别范围**（台词、哭喊、哼哈等语气音全部由配音轨覆盖）。

## 事件类型标注体系（四类，不许发明变体；限定词写括号或列尾）

| 标注 | 含义 | 贴轨方处理 |
|---|---|---|
| 【自动】 | 物理动作/环境事件（打斗、脚步、水花、风、坍塌） | 可检索自动贴轨 |
| 【手动】 | 玄幻特效、UI 弹窗、转场字卡 | 人工/用户提供素材 |
| 【对白】 | 台词、表情特写段 | 不配，保留行 |
| 【待定】 | 风格化内容（Q版贴纸、卡通桥段） | 等用户定方向 |

> 注：明确可检索的特效声（自燃、爆炸、法阵展开）按题材库正货处理，拿不准就写清画面与声学诉求，别擅自归【待定】。

## 报告模板（表格必须逐秒一行；关键事件加粗；镜头切换标【切】）

```markdown
# <视频名> 视频动作分析（逐秒精扫）

> 时长 Xs（N 帧逐秒全扫，manifest 见 frames_<集号>/）。题材：<写实/玄幻/卡通...>
> 标注：【自动】=物理/环境可自动配；【手动】=特效/UI 人工；【对白】=不配；【待定】=风格化待定

## 剧情概要
（≤3 句，无人名考据）

## 全片环境判断
（全片时空底色一句话 + 候选环境底衬声方向，如「全片白天·麦田户外：风噪、风吹树叶/草地」；场景混杂则按场景分别给方向）

## 逐秒时间轴
| 时间 | 画面内容 | 声音事件（贴轨建议） | 类型 |
|---|---|---|---|
| 10 | 延续：女子低头开启信封 | 开信封起手动作：指与纸摩擦轻响（纸材质，Small） | 【对白】 |
| **11** | **延续：女子右手取出信封持于身前** | 抽信封动作：信封离匣摩擦轻响（纸材质，Small） | 【自动】 |
| **12** | **延续：信封递向老者** | 递出动作：纸面摩擦延续 + 手臂布料 movement 轻响（纸材质；movement 优先，画面无快速位移成分故不叠 whoosh） | 【自动】 |
| **13** | **延续：老者伸手接过信封，交接完成** | 接取落点动作：指尖触纸轻响收尾（纸材质，落点） | 【自动】 |
| **16** | **【切】延续镜头：黑衣侍卫入画，走至男子身后站定** | 入画行走动作：脚步 2-3 步（Medium，硬质地面；皮带金属扣微响为备注层）；注：未见行走中间帧，起手 15s 末-16s，贴轻量脚步 | 【自动】movement |

## 声音事件统计
- 【自动】N 个：逐条列出 时间+事件+起手/落点（可按事件链聚合：11-13s 取信封-递出-接过 = 1 条）
- 【手动】N 个：逐条列出（含待用户提供项）
- 【对白】约 Xs 不配

## 待用户拍板
（无法自决的事项逐条列出；确无疑点写「无」）
```

**反面示例**（真实翻车，同一动作的不合格写法）：`| 15-16 | 楼上：某人端坐茶桌（侍卫立其后） | 茶馆底衬延续 | 【自动】（弱） |` ——丢了「侍卫入画」这个动作事件本身，只剩环境，且合并行丢失起手点。

## 批量任务纪律（多集/整剧时）

- **每会话只跑 3~5 集**，跑完即落盘收尾；上下文压力是无感降级的第一诱因，会话间只靠磁盘产物（manifest + jsonl + 报告）衔接
- **校准集先行**：批量前先跑 1~2 集「已知答案」集（有合格样例或历史翻车的集），门禁全过、关键段落与已知事实一致，才放量
- **进度状态由门禁推导**：用 `check_report.py --dir` 的输出生成总清单状态，禁止手写「✅完成」——手写状态曾与磁盘产物脱节（报告已存在却标「待分析」）
- 写合并行的冲动出现 = 上下文过载的信号，立即落盘、结束会话、换新会话续跑

## 抽帧与长批实测坑（20260916 三十集连扫新增）

- **skill 自带抽帧脚本的 eq(n) 滤镜图会 OOM**：逐秒清单超长（>~60 项）时 ffmpeg 内存错误。实测等价替代：`ffmpeg -i x.mp4 -vf "select='not(mod(n,24))' -fps_mode vfr"`（24fps 每秒取首帧；其他帧率替换模数），**showinfo 回读逐槽校验 pts_time 为整秒 + 帧帧 md5 互异**，等价性即被证明，不要反复试错原脚本。
- **ffmpeg 新版（2026 构建）`-vsync vfr` 已弃用**：改 `-fps_mode vfr`，否则报警告且行为可能变化。
- **内容安全拦截（错误 1301）处置**：动画/真人题材都可能触发，且对同一帧**确定性复现**（重试无效还烧会话）。纪律：①判读文字一律中性技术性动作术语（「角色A躯干前倾」），禁止渲染性措辞；②单条调用被拦**不要重试同一调用**，跳过该帧用最简客观标签（「人物移动」「物体变化」）兜底，保证逐秒行不空洞；③同一集连续两次会话被拦 = 该集内容确定性触发，**跳过该集、上报制作人**（20260916 第02集两次拦截即此案），禁止整夜卡死。
- **批量读图提效**：帧图每批并行读取 ≥8~10 张（夜批实测短集 40~70s 全流程 10~15 分钟；逐张串行读会拖到 2~3 倍）。
